Quarto background (brief)

Quarto combines narrative text (Markdown), code (R/Python/etc.), and results in one reproducible file (.qmd). Rendering runs code top-to-bottom in a fresh R session, so your file must include every library, import, and object creation it uses.

Create a doc in RStudio: File > New File > Quarto Document (title/author/output can be changed in YAML).

Three parts: - YAML (between — at top) - Markdown text - Code chunks, e.g.:


```{r}
# Import our data
data <- read_csv("data.csv")
```

Useful chunk options: echo, eval, warning, message, fig-width/height, out-width, fig-align. You can set defaults in YAML (execute: …) and override per-chunk with hash pipe lines:

Paths: Prefer here::here() for robust project-root-relative paths across scripts and .qmd.

Common knit issues: object not found (dependence on Console), file not found (bad paths), duplicate chunk labels, typos/missing punctuation.

Micro-task: - Do: Add to YAML: format: html: toc: true code-overflow: wrap Check: Re-render and confirm TOC and wrapping.

# Import raw ----
raw_path <- here::here("data","raw","penguins_raw.csv")

# If you don't have the raw file yet, run ONCE to create from palmerpenguins:
# install.packages(c("palmerpenguins","janitor"))
# readr::write_csv(
#   janitor::clean_names(palmerpenguins::penguins_raw),
#   here::here("data","raw","penguins_raw.csv")

stopifnot(file.exists(raw_path))
penguins_raw <- readr::read_csv(raw_path, show_col_types = FALSE)

# Minimal clean ----
penguins_clean <- penguins_raw |>
  janitor::clean_names() |>
  dplyr::mutate(
    culmen_ratio = culmen_length_mm / culmen_depth_mm

# Save reusable dataset ----
processed_csv <- here::here("data","processed","penguins_clean.csv")
processed_rds <- here::here("data","processed","penguins_clean.rds")
readr::write_csv(penguins_clean, processed_csv)
saveRDS(penguins_clean, processed_rds)

library(tidyverse)
library(here)
library(readr)

Load saved dataset

# Preferred: load the saved dataset created by scripts/00_import_penguins.R
penguins_clean <- readRDS(here::here("data","processed","penguins_clean.rds"))
# Alternative:
# penguins_clean <- readr::read_csv(here::here("data","processed","penguins_clean.csv"))

Summary

penguins_summary <- penguins_clean |>
  dplyr::select(species, island, culmen_length_mm, culmen_depth_mm, flipper_length_mm, culmen_ratio) |>
  tidyr::drop_na(culmen_length_mm, culmen_depth_mm, flipper_length_mm) |>

  dplyr::summarise(
    mean_flipper_length = mean(flipper_length_mm),
    mean_culmen_ratio   = mean(culmen_ratio),
    .groups = "drop"
  )

Responsible AI: warnings, “vibe coding,” and prompting (15–20 min)

Definition — “Vibe coding”: - Generating/accepting code because it “looks right,” without understanding or testing. - Signs: overly verbose pipelines, unused objects, magic numbers, ignoring warnings/errors, piling tweaks until it runs “by luck.”

Risks to watch: - Hallucinations: invented functions/arguments; wrong package names. - Out‑of‑date training: advice for old APIs or options. - Over‑verbosity: unnecessary mutate/select/filter steps that obscure logic.

How to avoid vibe coding: - Ask for minimal diffs: “Propose the smallest change to fix this and explain why it works.” - Specify constraints: “R 4.x, tidyverse only, readr IO, no setwd(), use here::here().” - Verify against docs: ?function, help pages, package sites. - Test immediately; keep a clean script; avoid adding packages without need.

Prompting tips (R + tidyverse): - Provide the smallest reproducible context: error message, a few rows/column names, target outcome. - State preferences: “Use dplyr verbs; concise, idiomatic code; no data.table.” - Ask to cite function/argument names you can verify in tidyverse docs. - Example prompt: - “In R 4.3 with tidyverse: This errors mutate(culmen_ratio = culmen_length / culmen_depth). My columns are culmen_length_mm, culmen_depth_mm. Propose the smallest fix; no new packages; add one-line NA-safe check.”

Good uses: - Debugging typos/arguments quickly - Explaining code you don’t recognise - Generating comments and section headers - Suggesting small, readable refactors

Reflection (add a short comment in your script or .qmd): - What did you ask AI? What change did you accept and how did you verify it? - Did AI propose anything wrong/outdated? How did you detect and correct it?
